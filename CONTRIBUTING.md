# Как поучаствовать

## Поднять у себя

```bash
python -m venv .venv
.venv/Scripts/activate          # Linux/macOS: source .venv/bin/activate
pip install -r requirements-dev.txt

cp .env.example .env            # вписать BOT_TOKEN, по желанию ITAD_API_KEY
python -m bot.main
```

## Перед пул-реквестом

```bash
ruff check . && ruff format . && mypy && pytest
```

Ровно это гоняет CI на Python 3.11 и 3.12 — если локально зелено, там тоже
будет зелено.

## Что важно в этом проекте

**Не писать код под API, который не проверил.** Схемы источников меняются, а
некоторые ведут себя неочевидно: ITAD, например, молча игнорирует незнакомые
поля фильтра и отвечает `200 OK`, так что «эндпоинт ответил» ничего не
доказывает. Перед работой с новым эндпоинтом:

```bash
python scripts/probe_apis.py            # все источники
python scripts/probe_apis.py itad steam # только нужные
```

Всё, что уже выяснено про источники, лежит в [docs/api-notes.md](docs/api-notes.md).
Нашёл новую особенность — допиши туда.

**Тесты на настоящих данных.** Слепки в `tests/conftest.py` сняты живыми
запросами. Пара ошибок проскочила именно потому, что тесты работали на
выдуманных значениях: ключ `i:<uuid>` не упаковывался в `callback_data`
из-за двоеточия, а даты из SQLite без зоны роняли график при встрече с
датами ITAD. Если добавляешь разбор ответа — возьми настоящий фрагмент.

**Честность цен важнее красоты.** У ITAD нет региональных цен для
Казахстана, поэтому цены Steam, GOG и Epic берутся у самих витрин, а
остальные помечаются знаком `≈`. Не выдавай пересчёт за точную цену.

## Стиль

- Комментарии и сообщения бота — по-русски, код и имена — по-английски
- Комментарий объясняет **почему**, а не что делает строка
- Файлы до 500 строк
- Типы везде, `mypy --strict` без послаблений

## Ошибки

В issue полезнее всего: что нажал, что ожидал, что получил, и по возможности
название игры и магазин — почти все находки в этом проекте начинались
со скриншота с конкретной игрой.
