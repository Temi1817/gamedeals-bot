## Главное: региональных цен для Казахстана у ITAD нет

`country=KZ` ITAD принимает, но отдаёт **международный прайс в долларах**.
Параметр работает не для всех стран:

| Страна | Валюта в ответе |
|---|---|
| DE | EUR |
| PL | PLN |
| TR | TRY |
| GB | GBP |
| **KZ, UA, RU** | **USD** |

Сначала это выглядело как обычный откат на доллары. На деле хуже —
магазины продают казахстанцам **заметно дешевле**, чем по международному
прайсу:

| Cyberpunk 2077 | ITAD для KZ | Реально для KZ |
|---|---|---|
| GOG | $17.99 (было $59.99) | **$8.99** (было $29.99) |

| Игра в Epic | Через ITAD | Реально |
|---|---|---|
| HITMAN World of Assassination | ≈12 807 ₸ | **5 184 ₸** |
| Dead by Daylight | ≈3 656 ₸ | **2 480 ₸** |
| Crimson Desert | ≈25 618 ₸ | **22 399 ₸** |

**Вывод:** цены Steam, GOG и Epic берём у самих витрин и подменяем ими
данные ITAD. Остальные магазины остаются международными и помечаются `≈`.

Исторический минимум от ITAD тоже международный, поэтому текущая
региональная цена может оказаться **ниже** «минимума за всё время». Это не
ошибка расчёта — такой минимум помечен словом «международный».

## IsThereAnyDeal

Документация: <https://docs.isthereanydeal.com/> ·
машиночитаемая схема: `https://docs.isthereanydeal.com/openapi.json`

Лимит: **1000 запросов / 5 минут**. Все ответы идут через кэш.

### Ключ — не Client ID и не Client Secret

При регистрации приложения выдаются три значения. Нужен **API Key**:
`?key=<...>` или заголовок `ITAD-API-Key`. Client ID и Secret — это OAuth
для доступа к вишлисту пользователя, для цен не нужны.

### Неизвестные поля фильтра молча игнорируются

Запрос с выдуманным параметром возвращает **200 OK**, а не ошибку. То есть
«эндпоинт ответил» ничего не доказывает: фильтр мог не примениться.

Проверять нужно различающими тестами — например, отсортировать по
возрастанию скидки и убедиться, что после `cut.min=75` мелких скидок нет.

Так вскрылось, что `minCut` и `maxPrice`, которые казались очевидными
именами, **не существуют**. Фильтры передаются одним полем `filter` с
URL-кодированным JSON:

```json
{
  "cut":        {"min": 75, "max": null},
  "price":      {"min": null, "max": 10},
  "type":       [1],
  "steamCount": {"min": 50, "max": null},
  "steamPerc":  {"min": 60, "max": 100}
}
```

Диапазон требует **обоих** концов, отсутствующий край — `null`.
`type: [1]` оставляет только игры, отсекая DLC и издания.

А вот значение `sort` **проверяется**: неизвестное даёт `400`. Два поля
одного эндпоинта ведут себя по-разному.

### Сортировка по `-cut` делает фильтр скидки бессмысленным

При `sort=-cut` наверху всегда скидки под 100%, поэтому кнопки «от 50%» и
«от 75%» визуально ничего не меняли — порог и так был выполнен. Выдача при
пороге 0, 50, 75 и 90 была побайтово одинаковой.

Решение: `sort=-trending`. Скидки в списке становятся разными, и порог
начинает работать.

### Порог качества против мусора

Без фильтра по отзывам выдача забита ассет-флипами: десятки безымянных игр
с одинаковым ценником `13 722 ₸ → 682 ₸` и скидкой −95%. Помогает
`steamCount ≥ 50` и `steamPerc ≥ 60`. Настоящие раздачи вроде Cardpocalypse
порог переживают.

### Прочие мелочи

- Тело POST-эндпоинтов — **голый массив** ID: `["uuid"]`. `{"ids": [...]}`
  даёт `400`.
- `prices/v3` с `deals=true` оставляет **только магазины со скидкой** — для
  Cyberpunk это один GOG вместо четырёх. Для карточки нужен `deals=false`.
- Цена приходит парой: `amount` (17.99) и `amountInt` (1799, в центах).
- `/stats/most-waitlisted/v1` и `/stats/most-popular/v1` работают, но окна
  «за сегодня» у них нет — это накопительные рейтинги. И **Steam appid они
  не отдают**, поэтому подменить цену родной в топе нечем.

## Steam

Неофициальный, но стабильный.

```
GET store.steampowered.com/api/appdetails?appids=<id>&cc=kz&filters=price_overview
GET steamcommunity.com/actions/SearchApps/<query>
GET store.steampowered.com/api/featuredcategories?cc=kz&l=russian
```

- Цены в **минорных единицах**: `1799900` при `KZT` = 17 999 ₸.
- `initial_formatted` приходит **пустой строкой** при нулевой скидке —
  старую цену считаем сами из `initial`.
- **Батч работает**: `appids=1091500,377160` возвращает обе игры.
- Нужно терпеть `success: false`, `data: []` вместо объекта и отсутствие
  `price_overview` у free-to-play.
- В `featuredcategories.top_sellers` попадают железки («Steam Machine» с
  нулевой ценой, четыре раза подряд) — чистим и дедуплицируем по appid.

## GOG

```
GET catalog.gog.com/v1/catalog?query=like:<title>&countryCode=KZ&locale=en-US
```

Тот же эндпоинт, что у поиска на сайте. Ключа не требует, страну принимает
параметром. Отдаёт `finalMoney` / `baseMoney` с суммой и валютой, скидку
строкой `-70%` и `storeLink`.

Сопоставляем **строго по точному названию**: «Cyberpunk 2077» и «Cyberpunk
2077: Ultimate Edition» — разные товары с разной ценой.

Старый `embed.gog.com/games/ajax/filtered` возвращает пустой список.

## Epic Games

### Что закрыто

- `store.epicgames.com/graphql` — **403**, Cloudflare.
- `egs-platform-service.store.epicgames.com` — **403**.
- `catalog-public-service-prod*.ol.epicgames.com` — **401**, нужна
  авторизация.

Легко сделать поспешный вывод, что цен Epic не достать. Это не так —
проверять надо соседние пути **рабочего** хоста.

### Что открыто

```
GET store-site-backend-static.ak.epicgames.com/freeGamesPromotions
GET store-site-backend-static.ak.epicgames.com/storefrontLayout
```

`storefrontLayout` — витрина целиком, около **300 игр** с ценами в валюте
региона, без ключа и без Cloudflare. Внутри именованные блоки: `Top
Sellers`, `Trending`, `Most Played`, `Top New Releases`, `Top Free to
Play`, `Coming Soon`.

Две ловушки:

1. **Локаль обязательно английская.** С `locale=ru` названия приходят
   переведёнными — «Мир наёмных убийц HITMAN» — и не сходятся с названиями
   от ITAD, по которым идёт сопоставление.
2. **Предложения в блоке обёрнуты** в `{id, namespace, offer}`, название и
   цена лежат уровнем глубже. Первая версия из-за этого вернула пустой
   список.

### Раздачи

`discountPercentage` у Epic — это **сколько процентов цены платит
покупатель**, а не размер скидки. `0` — раздача, `25` — распродажа −75%.
Наивная проверка «есть промо → раздача» тащит в `/free` обычные скидки.

`productSlug` часто `null` — ссылку собираем из `offerMappings[0].pageSlug`,
затем `catalogNs.mappings`, затем `productSlug` без хвоста `/home`.

## CheapShark

Ключа не требует, схема совпадает с документацией. Числа приходят
**строками**: `"59.99"`, `"0.000000"`.

Цены **только в USD** и в основном ключи реселлеров, поэтому такие
предложения помечены `is_reseller` и никогда не считаются «лучшей ценой».

Справочник магазинов тянем **один раз на вызов**: упавший `/stores`
иначе умножается на число предложений в ответе.

## Курсы валют

```
GET open.er-api.com/v6/latest/USD
```

166 валют одним запросом, без ключа, обновление раз в сутки. Альтернатива —
[Нацбанк РК](https://nationalbank.kz/rss/rates_all.xml), но он даёт только
пары к тенге.

Недоступный курс **не роняет карточку** — просто пропадает строка с
пересчётом.

## Календарь распродаж: API нет

Ни у ITAD, ни у Steam. SteamDB отдаёт `403`, и парсить его нельзя.

Даты Valve публикует заранее через Steamworks — например, зимняя
распродажа 2026 объявлена на 17 декабря — 4 января. Но машиночитаемого
источника не существует: если делать календарь, это будет файл в
репозитории, обновляемый руками.

## Грабли не из API

### `callback_data` и двоеточие

aiogram разделяет поля `callback_data` двоеточием. Ключ игры вида
`i:<uuid>` не упаковывается вовсе:

```
ValueError: Separator symbol ':' can not be used in value
```

Падало на сборке клавиатуры, то есть **поиск не работал ни разу**. Ключ
теперь `i~<uuid>` — 43 байта из 64 доступных.

Тесты это пропустили, потому что работали на выдуманных `itad-1`, где
двоеточия нет. Сейчас есть `tests/test_keyboards.py` с настоящими
идентификаторами.

### Alembic глушит логи

`fileConfig()` перенастраивает логирование **целиком** по `alembic.ini`,
где `root` стоит на `WARN`. После миграций все INFO-логи бота исчезали.
Лечится флагом `configure_logger=False` в `cfg.attributes`.

### Деньги и SQLite

SQLite не умеет `NUMERIC` нативно и гоняет значения через float. Храним
целым числом минорных единиц через свой тип `Money` — точно и одинаково
ведёт себя в SQLite и Postgres.

### Пропорция вместо курса

Старая цена сначала выводилась пропорцией от новой. При скидке −100% новая
цена равна нулю, пропорция не считается, и в списке появлялось
`$14.99 → 0 ₸` — доллары рядом с тенге. Переводим курсом, отдельным полем
`converted_regular_price`.

### Кириллица в нормализации имён

Регулярка `[^a-z0-9]+` для канонических имён магазинов вырезала кириллицу
целиком: любой магазин с нелатинским названием превращался в пустой ключ и
сливался со всеми такими же. Нужно `[\W_]+` с `re.UNICODE`.
